# Skills Inventory — {candidate name}

Every skill listed here must have at least one **Evidence** link (a bullet ID
from `master_experience.md` or a named project). If you can't cite evidence,
the skill doesn't belong here — the Auditor rejects any CV that claims a
skill without evidence. Skills claimed in source documents but not yet
evidenced live in `unevidenced.md`, permanently CV-ineligible until
evidenced (via /enrich).

---

## Schema

```
- **Skill name**
  - Proficiency: native | advanced | working | familiar
  - Recency: year last used
  - Evidence: [BULLET_IDs or project names]
  - Context (optional): how/where it was used
```

Proficiency definitions:
- **native** — can operate as the domain authority
- **advanced** — independent, can mentor, can debug non-trivially
- **working** — independent on typical tasks, occasional lookups
- **familiar** — can read, follow tutorials, pair with stronger user

Section headers group by category (## Programming Languages, ## Data &
Analytics, ## Product, ## Methodologies, ## Languages). The `## Languages`
section lists spoken languages with CEFR levels; they need no Evidence line.
